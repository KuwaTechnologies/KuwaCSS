# KuwaCSS v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish `kuwacss` 0.1.0: the stylesheet, the generated AI-contract files, the `kuwacss check` and `kuwacss init` CLI, tests, and CI, in the repository `KuwaTechnologies/kuwacss`.

**Architecture:** `src/vocab.ts` is the single source of truth for every class. A generator emits the utility CSS, the primitive container rules, `vocab.json`, `kuwa.d.ts`, and `llms.txt` from it. Hand-written CSS covers tokens, reset, classless elements, primitive child rules, and components. A bundler concatenates everything into cascade layers and minifies with Lightning CSS. The CLI is dependency-free JavaScript that reads `vocab.json`.

**Tech Stack:** Node 22 (native TypeScript type stripping for `src/` and `test/`), `node:test`, Lightning CSS, `gpt-tokenizer` (dev, token budget test), `axe-core` (dev), preinstalled Playwright for browser tests. Zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-04-kuwacss-framework-design.md`

## Global Constraints

- Package name `kuwacss`; repository `https://github.com/KuwaTechnologies/kuwacss`; licence MIT; version `0.1.0`.
- `dist/kuwa.min.css` gzipped must be 10,240 bytes or smaller.
- `dist/llms.txt` must be 2,500 tokens or fewer (cl100k tokenizer).
- Browser floor: Baseline 2024. Lightning CSS targets: chrome 120, firefox 121, safari 17.4.
- No `!important` anywhere except the `prefers-reduced-motion` rule.
- Every selector in `reset.css` and `base.css` is wrapped in `:where()`.
- Layer order, exact: `@layer kuwa.tokens, kuwa.reset, kuwa.base, kuwa.layout, kuwa.components, kuwa.utilities;`
- Scales, exact: space `0 xs s m l xl 2xl 3xl`; text `xs s m l xl 2xl 3xl 4xl`; roles `primary success warning danger info`; prefixes `m` 48rem, `l` 64rem, `xl` 80rem.
- Responsive whitelist, exact 14: `hidden block stack row cols-1 cols-2 cols-3 cols-4 text-left text-center text-right order-first order-last grow`.
- `left`/`right` utilities map to `inline-start`/`inline-end`; `top`/`bottom` map to `block-start`/`block-end`.
- The CDN URL in generated text uses the current major from `package.json`: `https://cdn.jsdelivr.net/npm/kuwacss@<major>/dist/kuwa.min.css` (so `@0` for this release; the spec's `@1` is the 1.0 form).
- Published CLI files are plain `.js` so the CLI runs on Node 18+; `.ts` is used only for `src/` and `test/`, which require Node 22+.
- Deviation from spec tooling: `node:test` instead of Vitest, to keep dev dependencies to three packages. Pixel-diff visual regression is deferred to 1.0; v0.1 browser tests check computed styles, contrast, and axe.

## Review Focus

1. A `class` attribute spanning lines with repeated spaces or duplicate tokens: the extractor splits on any whitespace and reports each distinct class once per line. Test in Task 8.
2. `kuwacss check` on a file with no class attributes, or on invalid UTF-8: zero findings, exit 0, no stack trace. Test in Task 8.
3. `data-theme="light"` nested inside `data-theme="dark"`: the inner subtree renders light. Test in Task 4.
4. A flex child with a long unbroken string: `row` child with `min-width-0` shrinks instead of overflowing the viewport. Test in Task 5.
5. `hidden m:stack` on an element: hidden below 768px, a flex column at or above it. Test in Task 3 (generated CSS) and Task 5 (computed style).

### Task 2: Vocabulary source of truth

**Files:**
- Create: `src/vocab.ts`
- Test: `test/vocab.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export const SPACE: readonly string[]; export const TEXT: readonly string[];
  export const ROLES: readonly string[]; export const PREFIXES: Record<'m'|'l'|'xl', string>;
  export const RESPONSIVE: readonly string[];            // the 14 names
  export type Kind = 'utility' | 'primitive' | 'component' | 'modifier' | 'adjective';
  export interface Entry { name: string; group: string; kind: Kind; css?: Record<string,string>;
    knobs?: Record<string,string>; appliesTo?: string[]; description: string; }
  export function entries(): Entry[];                   // every valid class, name unique
  export const TRANSLATIONS: Record<string,string>;     // foreign spelling -> kuwa spelling
  ```

- `css` is present for every `utility` and `primitive` (container declarations only; primitives reference `var(--gap, var(--space-m))` etc.). `css` is absent for `component`, `modifier`, and `adjective`-kind entries that are hand-written (`card`, `badge`, `alert`, `prose`, `switch`, `icon`, `button`, `primary`, `ghost`, `danger`, `small`, `large`, `success`, `warning`, `info`). Bare weight and style adjectives (`bold`, `italic`, ...) are `utility` kind with `css`.
- Groups, exact: `layout`, `children`, `alignment`, `spacing`, `typography`, `color`, `box`, `sizing`, `display`, `position`, `interaction`, `component`.
- Role colour utilities: `bg-{role}` css is `{ background: var(--{role}), color: var(--on-{role}) }`; `bg-{role}-soft` is `{ background: var(--{role}-soft), color: var(--{role}-text) }`.
- `TRANSLATIONS` contains at least: `p-4`→`padding-m`, `px-4`→`padding-x-m`, `mt-2`→`margin-top-s`, `w-full`→`width-full`, `h-full`→`height-full`, `sr-only`→`visually-hidden`, `font-bold`→`bold`, `text-lg`→`text-l`, `text-sm`→`text-s`, `rounded-lg`→`rounded-l`, `shadow-md`→`shadow`, `items-center`→`align-center`, `justify-between`→`justify-between`? no (already valid; omit), `btn`→`button`, `btn-primary`→`primary`, `d-none`→`hidden`, `container-fluid`→`container`, `mx-auto`→`margin-x-auto`, `flex-col`→`stack`, `grid-cols-3`→`cols-3`.
